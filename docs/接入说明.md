# 参考文献格式检查器 · 鸿蒙 PC 校园应用（选题 054）

**项目定位**：帮学生/研究者维护参考文献清单，自动检查「缺字段」和「重复项」，并批量修正。
**原型档位**：本地 —— 数据内置，不联网、不读文件系统、不需要账号。

---

## 三步接入 DevEco

### 1. 建一个空工程

DevEco Studio → 新建项目：

| 项 | 填什么 |
|---|---|
| 项目名称 | **`RefCheck`**（建议，别用默认的 `MyApplication`） |
| 包名 | `com.example.refcheck`（自动带出，可不动） |
| 保存路径 | **默认就行** `C:\Users\THUNDER\DevEcoStudioProjects\RefCheck` |
| Compatible SDK | `6.1.1(24)`（默认） |
| 模块名称 | `entry` |
| 设备类型 | ✅ **只勾 `2in1`**（这就是鸿蒙的 PC / 平板二合一） |

### 2. 替换页面

把本目录的 `Index.ets` **整份内容**覆盖到：

```
entry/src/main/ets/pages/Index.ets
```

### 3. 改设备类型（**必做，否则 PC 模拟器里装不上**）

新建工程默认 `deviceTypes` 可能是 `["phone"]`。打开：

```
entry/src/main/module.json5
```

把

```json5
"deviceTypes": [
  "phone"
],
```

改成

```json5
"deviceTypes": [
  "2in1"
],
```

> 如果你建工程时勾了 2in1，这里可能已经是 `2in1`，就不用改。

### 4. 建 PC 模拟器并运行

Device Manager → 新建模拟器 → 类型选 **2in1** → 启动 → 点绿色运行按钮。

## 演示脚本（照着点，截图就出来了）

**页面上有什么**

- 顶部：标题 `参考文献格式检查器` + 右上角标签 `选题 054 · 本地档`
- 一条副标题说明
- 三个按钮：**开始检查**（金色）/ 批量修正 / 重置
- 下面 10 条引用，每条显示：编号 · 作者 · 年份 / 题名 / 期刊 / DOI

**演示顺序（约 60 秒）**

| 步骤 | 动作 | 画面 |
|---|---|---|
| 1 | 打开应用 | 10 条引用，边框都是灰色 = **还没检查** |
| 2 | 点 **开始检查** | 顶部弹出横幅：**检查不通过 · 6 条有问题，共 8 处** |
| 3 | 看列表 | 6 条问题条目变**红边红底**，底下挂出标签：`缺少作者` / `缺少年份` / `缺少 DOI` / `DOI 与其它条目重复` / `题名与其它条目重复` |
| 4 | 点 **批量修正** | 回到未检查状态，肉眼可见缺字段被补上（`待补作者`、`2024`、`10.0000/pending.r07`…） |
| 5 | 再点 **开始检查** | 横幅变成 **检查通过 · 全部 10 条引用格式完整**（绿色） |

**这就是「检查 → 判定 → 修正 → 复查」的完整闭环。**

**埋了什么问题（对照用）**

| 编号 | 问题 |
|---|---|
| R01 | 与 R06 撞车：DOI 重复 + 题名重复（**被牵连**，改任一条即解开）|
| R02 | 缺年份 |
| R04 | 缺作者 |
| R06 | 与 R01 撞车：DOI 重复 + 题名重复 |
| R07 | 缺 DOI |
| R10 | 缺题名 |

> 合计 **6 条 / 8 处** ——「重复」会同时标在双方身上，所以 R01 也计为问题条目。

## 判断规则（写在 README 里给老师看）

| # | 规则 |
|---|---|
| 1 | 作者、题名、期刊名、DOI 任一为空 → 判「缺少」 |
| 2 | 年份为空 → 判「缺少年份」；年份不是 4 位 → 判「年份应为 4 位」 |
| 3 | DOI 在清单中出现多次 → 判「DOI 与其它条目重复」 |
| 4 | 题名在清单中出现多次 → 判「题名与其它条目重复」 |
| 5 | 全部条目都没有问题 → 结论「检查通过」；否则「检查不通过」并给出问题条数与处数 |

## 可能踩的坑

1. **`deviceTypes` 没改成 `2in1`** → 模拟器列表里看不到你的应用
2. **模拟器没建** → Device Manager 里新建一个 `2in1` 类型的
3. **ArkTS 报类型错误** → 本文件所有函数都写了显式类型；若 DevEco 提示某个 API 不认，优先看 `.fontColor()` / `.border()` / `.backgroundColor()` 三个方法的参数形态（对象 vs 值）
4. **`@Builder` 里用 `if`** → ArkUI 支持，但 `if` 必须直接放在 `build()` 或 `@Builder` 的根级，本文件已经这么写了

## 为什么选这个题（一句话）

它和作者另一个开源项目（RAG 评测平台的门禁机制）是同一套心智：**先定规则 → 逐条判 → 给出通过/不通过 → 列出问题清单 → 支持批量修正**。
区别只是把「逐句核对有没有依据」换成了「逐条核对字段齐不齐」。
